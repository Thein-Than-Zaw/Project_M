# DEV-09A working scope — durable private notification inbox

Authority: owner continuation after the DEV-09 recommendation; requirements v1.1 F09 NOTIFY-01–03 / AC-F09-01–03 and AC-F09-05, D06 in-app only. Preserve current uncommitted DEV08-UI02 local call/settings revision and explicit deployment hold. Use Developer Implementation and Task Management skills against the existing Java/Spring/PostgreSQL project; no framework/provider change.

Bounded outcome: own persistent inbox, unread badge, all/unread filter, cursor pagination, mark read/unread, safe target navigation, REST catch-up after offline/login, recipient-only live invalidation through existing authenticated pairing queue. Store new committed partner message/gift, new memory, missed call and partner-joined events; no historical backfill or payload previews. Source event + recipient + type deduplicate. Business event and inbox insert commit atomically, followed by best-effort private WS invalidation. If WS fails, REST polling/reconnect catches up. Sound controls remain exclusively under Notification Settings; inbox mark-read does not mark a chat message read.

V22 adds notification_inbox with recipient/space membership FK, immutable source/target/type metadata, generated sequence, created/read timestamps, version and recipient paging/unread indexes. Targets have no content FK, so purged memory notifications remain generic with an unavailable-target response. GET /api/notifications?before=sequence&unreadOnly=false returns newest25, nextCursor, unreadCount. PATCH /api/notifications/{id} {read:boolean,version:long}; stale opposing update409, same-state retry succeeds. GET /api/notifications/{id}/target rechecks membership and resource availability; body is {available,url}. No client recipient/type/event creation API. Common server errors and CSRF apply.

Supporting UI: Bell/Notifications navigation on Home/Chat/Memories opens an inbox drawer (call remains full-page). New content uses textContent, generic labels, Myanmar timestamps, no sender/message/media preview. Loading/empty/error/retry, keyboard close, unread state, load older, conflict and unavailable-target states are required. Opening the inbox does not auto-clear unread; Open marks that item read after server target validation. Clicking a target navigates normally; existing page-leave call behavior is unchanged.

Outside this increment: scheduler/reminder policies, presence/typing, password/account/session enhancements, retention auto-delete, notification deletion and external push. Retention/reminder decisions remain open; no 90-day policy or unlimited storage guarantee is implied. No automatic deletion until a retention rule is selected. No retroactive notification population. Settings remain device-local as already disclosed.

Plan: implement V22/service/controller/transaction event hooks; add private queue invalidation + shared UI and existing-page refresh hooks; verify real local PostgreSQL/API/WS permissions, offline catch-up, duplicate/rollback, source eligibility, target deletion and read conflicts; build, local upgrade and smoke. Preserve existing accounts/files. No Neon writes, Git push or Render deployment.

Coverage: AC-F09-01 offline REST/UI catch-up; AC-F09-02 source-event dedup/unread count; AC-F09-03 recipient ACL and denied guessed IDs; AC-F09-05 existing expiry redirect plus inbox401 recovery.
