Architecture: no migration or API contract change. SecurityConfig only adds the public static /browser-notifications.js module. Sound engine shares one master gain across sent/received/ringtone/preview; notification mute and volume0 keep audio silent without touching WebRTC tracks or partner media. Settings are device/browser-local, persisted and synchronized between same-origin tabs. Sent sound only follows a matching committed own server message for an intent actually transmitted from this page; queued/failed/sender-history/duplicate receipt/replay does not chime. Reconciled committed response can acknowledge a pending transmitted intent once.

Browser API: defaultOff; requestPermission only in the explicit switch's user gesture. Denied/dismissed/unsupported permission stays off with actionable Settings feedback. Existing permission grants are reused without a new prompt; Off is an app preference and cannot revoke browser-level permission. The UI reports both. Native notices use generic constant text (no body/note/title previews), silent:true to avoid OS/app double sounds, stable tags + bounded shared seen IDs and navigator.locks when available. App sound mute preserves visual notices. Browser/OS support and sound suppression differ by platform; a constructor failure is caught and reported, preserving in-app alerts. This increment targets supported desktop browsers; actual mobile native-notification support is not claimed.

Automatic alerts are only emitted while backgrounded, with an expiring same-origin foreground-tab lease to suppress popups when another app tab is focused. Initial inbox load/history never triggers a popup; subsequent refreshed new unread entries can show the latest generic update per batch. Incoming Voice/Video has its own generic alert; clicking focuses the existing app and reveals the call without answering automatically. Popup Open on an active call keeps the call view visible instead of opening an inert inbox dialog over it. Terminal calls, Off and pagehide dispose pending/visible popups; queued permission/lock operations cannot create alerts after logout/page disposal. Web Locks fallback is best-effort shared storage + native notification tag, not a universal cross-browser delivery guarantee.
